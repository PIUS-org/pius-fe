# 테스트 시나리오 — PiUS 업무관리 시스템

기획자 피드백 1·2차 반영분을 확인하기 위한 시나리오다.
**위에서 아래로 순서대로** 진행하면 된다. 앞 단계가 뒤 단계의 전제가 되는 곳이 있다.

접속: **https://admin.pius.co.kr** · 비밀번호는 전부 `0000`

| 계정 | 역할 | 쓰는 곳 |
| --- | --- | --- |
| `master` | 마스터 | 주민번호 열람. §1 · §7 |
| `siochoi` | 정직원 (최시온) | 대부분의 시나리오 |
| `haneul` | 용역 (이하늘) | 권한 제한 확인. §8 |

> **첫 접속은 15~25초 걸린다.** 유휴 상태에서 서버가 깨어나는 시간이고 버그가 아니다.
> 한 번 뜨면 그 뒤로는 즉시 응답한다.

---

## 1. 주민등록번호 — 마스터만 전체 열람

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 1-1 | `siochoi` 로 로그인 → 인사관리 → 아무 인력 클릭 | 주민번호가 `9601**-*******` 로 마스킹. **`보기` 버튼이 없다** |
| 1-2 | 로그아웃 → `master` 로 로그인 → 같은 인력 | 마스킹 옆에 **`보기`** 버튼이 있다 |
| 1-3 | `보기` 클릭 | 전체 번호가 나온다 (예: `960115-1234567`) |
| 1-4 | `가리기` 클릭 | 다시 마스킹으로 돌아간다 |

> 정직원이 못 보는 것이 정상이다. 인사 접근 권한과 별개로 한 단계 좁게 잡았다.
> 누가 언제 누구 번호를 열었는지는 서버 로그에 남는다.

## 2. 인사 목록 — 열 위치 고정

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 2-1 | 인사관리 → **재직** 탭 | 고용형태 · 직무 열 위치를 눈으로 기억 |
| 2-2 | **퇴사** 탭으로 전환 | 입사일 칸이 `2023-08-21 ~ 2026-05-31` 로 길어져도 **열 위치가 그대로** |
| 2-3 | **전체** 탭 | 한 줄짜리와 두 날짜짜리가 섞여도 열이 안 흔들린다 |

## 3. 전화번호 검색

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 3-1 | 검색창에 `010-4412-8890` | 김도현 1명 |
| 3-2 | `01044128890` (하이픈 없이) | **똑같이 1명** |
| 3-3 | `44128890` (뒷자리만) | 똑같이 1명 |

> 1차 피드백에 "하이픈이 필수"라고 주신 건 최시온의 번호가 데이터에서 바뀌어 있어서였다.
> 기능 자체는 처음부터 정상이었다. 화면에 보이는 번호로 검색하면 항상 맞는다.

## 4. 수금 관리 (신규)

프로젝트관리 → 아무 프로젝트 → **기본정보** 탭 하단 `수금 내역`

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 4-1 | 카드를 본다 | 기존 수금이 날짜·금액·구분과 함께 목록으로. 맨 아래 **합계** |
| 4-2 | 합계와 위쪽 **수령액** 비교 | 두 값이 같다 (수령액은 이 목록의 합계다) |
| 4-3 | `수금 등록` → 입금일·구분(선금/중도금/잔금/기타)·금액 입력 → 저장 | 목록에 추가되고 **수령액이 즉시 늘어난다** |
| 4-4 | 거래처관리 → 그 프로젝트의 거래처 → 업무정보 탭 | **누적 수령이 늘고 미수금이 줄어 있다** |
| 4-5 | 수금 한 건 `수정` → 금액 변경 → 저장 | 합계·수령액·거래처 미수금이 모두 따라 바뀐다 |
| 4-6 | 수금 `삭제` → 확인창에서 `삭제` | 목록에서 빠지고 금액이 원래대로 돌아온다 |
| 4-7 | 계약금액보다 큰 금액을 등록 | **막지 않는다.** 합계가 빨간색 + "계약금액보다 많이 수금되었습니다" |

> 4-7 을 막지 않는 것은 의도다. 선금·정산처럼 계약금을 넘겨 받는 경우가 실무에 있어
> 막으면 입력 자체가 불가능해진다. 대신 눈에 띄게 표시한다.

## 5. 퇴사일 인수인계 경고 (신규)

**주의: 5-1 · 5-3 은 취소로 끝낸다.** 실제로 저장하면 그 사람이 퇴사 처리된다.

### 5-1. 정직원 — 담당 프로젝트가 있는 경우
1. 인사관리 → **최시온** → 인사정보 탭
2. **퇴사일**에 미래 날짜(예: `2026-12-31`) 입력
3. `변경사항 저장` 클릭

보여야 한다:
- `인수인계가 필요합니다` 창
- 담당 프로젝트 4건이 **완료된 건까지** 전부 나온다
- 각 항목에 빨간 **`담당자`** 표기
- 안내: "담당자가 비면 거래처 연락 채널이 끊기므로 반드시 인수인계해주세요"

4. **`취소`** 클릭 → 아무 일도 일어나지 않는다

### 5-2. 용역 — 진행중 프로젝트가 있는 경우
1. 인사관리 → **이하늘** → **계약종료일**에 미래 날짜 → 저장

보여야 한다:
- 창이 뜨고 **진행중 프로젝트만** 나온다 (완료 건은 안 나온다)
- `담당자` 표기가 없다 (용역은 담당자가 될 수 없다)
2. `취소`

### 5-3. 넘길 것이 없는 경우
1. 인사관리 → **고은채**(계약종료 용역, 완료 프로젝트만) → 계약종료일 변경 → 저장

보여야 한다: **창이 뜨지 않고 바로 저장된다**

## 6. 거래처 담당자 수정 (신규)

거래처관리 → 아무 거래처 → 기본정보 탭 → `담당자` 카드

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 6-1 | 담당자 행을 본다 | `수정` · `삭제` 버튼이 둘 다 있다 |
| 6-2 | `수정` 클릭 | 이름·직책·전화번호·이메일이 **기존 값으로 채워진 채** 열린다 |
| 6-3 | 이메일이나 전화번호를 바꾸고 `저장` | 목록에 반영된다 |
| 6-4 | `삭제` 클릭 | **확인창이 뜬다.** 이름이 문구에 들어 있다 |
| 6-5 | 확인창에서 `취소` | 담당자가 그대로 남아 있다 |

## 7. 참여인력 제거 확인창

프로젝트관리 → 참여인력이 있는 프로젝트 → **참여인력** 탭

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 7-1 | `제거` 클릭 | 확인창. 문구에 **제거 대상 이름**이 들어 있다 |
| 7-2 | 버튼 색을 본다 | `제거` 가 **빨간색** (되돌릴 수 없는 동작) |
| 7-3 | `취소` | 인원이 그대로 |

## 8. 용역 계정 권한

`haneul` 로 로그인

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 8-1 | 사이드바 | 인사관리 · 거래처관리가 막혀 있다 |
| 8-2 | 프로젝트관리 | **본인이 참여한 건만** 보인다 |
| 8-3 | 프로젝트 상세 | 계약금액이 `비공개`, **수금 내역 카드가 아예 없다** |
| 8-4 | 참여인력 탭 | 본인 용역비만 보이고 타인 것은 `비공개` |

## 9. 화면 문구 · 플레이스홀더

| | 확인 |
| --- | --- |
| 9-1 | 검색창의 회색 안내문이 **입력한 값과 확실히 구분**된다 (더 연해졌다) |
| 9-2 | 거래처 담당자 카드에 "추후 상세 기획 예정입니다" 문구가 **없다** |
| 9-3 | 거래처 진행여부에 "프로젝트 상태로 자동 판정" 문구가 **없다** |
| 9-4 | 거래처 업무정보 탭에 "계정관리" 카드가 **없다** |
| 9-5 | 로그인 화면 좌측 상단이 **PIUS MANAGEMENT SYSTEM** |

## 10. 인사 상세 — 담당 프로젝트 포함

| | 한다 | 보여야 한다 |
| --- | --- | --- |
| 10-1 | 인사관리 → **최시온** | 헤더에 `참여 프로젝트 4 / 진행중 3` |
| 10-2 | **프로젝트** 탭 | 4건이 나오고 역할이 전부 **`담당자`** |

> 최시온은 참여인력으로 등록된 프로젝트가 **0건**이다. 담당자로만 지정돼 있다.
> 예전에는 이 화면이 비어 있었다 — 그러면 "이 사람이 무슨 일을 했는지" 추적이 끊긴다.

## 11. 회귀 확인 (기존 기능이 안 깨졌는지)

| | 확인 |
| --- | --- |
| 11-1 | 인사 등록 → 계정이 함께 생기고 초기 비밀번호 `0000` |
| 11-2 | 거래처 등록 시 **사업자등록번호 중복**이 차단된다 |
| 11-3 | 프로젝트 목록에서 계약기간이 지난 진행중 건이 **빨간 글씨** (`생산실적 집계 고도화`) |
| 11-4 | 첨부파일 업로드 → 다운로드. **한글 파일명이 안 깨진다** |
| 11-5 | 퇴사자(`문가영`)가 참여했던 프로젝트에 **이름이 그대로 남아 있다** |
| 11-6 | 퇴사자 계정으로는 **로그인되지 않는다** |

> 11-5 가 이 시스템의 존재 이유다. 사람이 나가도 그 사람이 한 일은 남아야 한다.
