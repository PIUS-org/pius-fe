# 화면 정의서 — PiUS 업무관리 시스템 v1.0

Claude Design 목업(`PiUS 업무관리 시스템 v2.dc.html`) 기준.
각 화면이 사용하는 API 를 함께 정리한다.

---

## 0. 라우트 맵

| 라우트 | 화면 | 접근 권한 |
| --- | --- | --- |
| `/login` | 로그인 | 전체 |
| `/hr` | 인력 목록 | `MASTER` · `EMPLOYEE` |
| `/hr/new` | 인사 등록 | `MASTER` · `EMPLOYEE` |
| `/hr/[id]` | 인사 상세 | `MASTER` · `EMPLOYEE` |
| `/clients` | 거래처 목록 | `MASTER` · `EMPLOYEE` |
| `/clients/new` | 거래처 등록 | `MASTER` · `EMPLOYEE` |
| `/clients/[id]` | 거래처 상세 | `MASTER` · `EMPLOYEE` |
| `/projects` | 프로젝트 목록 | 전체 (용역은 본인 참여 건만) |

## 1. 로그인 `/login`

**레이아웃** — 좌우 2단 (`1.1fr : 1fr`)

| 영역 | 구성 |
| --- | --- |
| 좌측 (`accent-900` 배경) | `PIUS SYSTEM & CONSULTING` 케이스레이블 / `업무관리 시스템` 대제목 / 설명 문구 / 하단 저작권 |
| 우측 | 로고 · `로그인` 제목 · 아이디 · 비밀번호 · 안내 문구 · 로그인 버튼 (348px 카드) |

**API**: `POST /api/v1/auth/login`

**동작**
- 실패 시 카드 내 에러 메시지 표시
- "최초 발급 비밀번호는 0000 입니다. 비밀번호 변경 · 찾기는 다음 버전에서 제공합니다." 안내 고정 노출

## 2. 공통 셸 (로그인 이후)

**사이드바** — 폭 230px, `accent-900` 배경

| 영역 | 구성 |
| --- | --- |
| 상단 | 로고 + `PiUS` / `업무관리 시스템 v1.0` |
| 메뉴 | 인사관리 · 거래처관리 · 프로젝트관리 |
| 하단 | 내 이름 / `{권한} · {직무}` / 로그아웃 버튼 |

- 활성 메뉴: 좌측 3px `accent-300` 보더 + 배경 `rgba(242,242,243,.12)`
- 용역 계정: 인사관리 · 거래처관리에 `권한 없음` 배지, opacity 0.42, `cursor: not-allowed`
  → 클릭 시 **접근 권한 다이얼로그**

**API**: `GET /api/v1/auth/me`, `POST /api/v1/auth/logout`

**전역 다이얼로그 · 토스트**

| 이름 | 내용 |
| --- | --- |
| 접근 권한 없음 | "용역 계정은 인사관리 · 거래처관리에 접근할 수 없으며, 프로젝트는 본인이 참여한 건만 확인할 수 있습니다." |
| 토스트 | 우측 하단, `accent-900` 배경, 2.2초 후 자동 소멸 |

## 3. 인사관리

### 3-1. 인력 목록 `/hr`

| 영역 | 구성 |
| --- | --- |
| 헤더 | 케이스레이블 `인사관리` / 제목 `인력 목록` / 우측 `인사 등록` 버튼 |
| 필터 | 검색 인풋(이름·전화번호, 290px) · 세그먼트(전체 / 재직 / 퇴사) · 우측 `검색 결과 N명 · {범위}` |
| 테이블 | No · 이름 · 전화번호 · 고용형태 · 직무 · 입사일·퇴사일 · 재직여부 |
| 하단 | 페이지네이션 (`‹` 숫자 `›`) + `한 화면 12명` |

- 재직여부 태그: `재직` → `tag-accent`, `퇴사` → `tag-neutral`
- 행 클릭 → `/hr/[id]`

**API**: `GET /api/v1/persons?q=&status=&page=&size=12`

---

### 3-2. 인사 등록 `/hr/new`

| 영역 | 구성 |
| --- | --- |
| 상단 | `← 인력 목록` / 제목 / 설명 |
| 본문 좌 (700px) | **필수 인력정보** 카드 — 이름 · 주민등록번호 · 고용형태(라디오) · 입사일 · 휴대전화 · 주소 · 이메일 |
| | **계정 생성** 카드 — 아이디 · 초기 비밀번호(`0000` readonly) |
| | 하단 버튼 — `등록 완료 · 계정 생성` / `취소` |
| 본문 우 (300px) | **등록 플로우** 안내 패널 (`accent-100` 배경) |

**입력 규칙**
- 휴대전화: 숫자 입력 시 자동 하이픈
- 아이디: 영문+숫자 20자 이내
- 주민등록번호: 숫자 13자리

**API**: `POST /api/v1/persons` → 성공 시 `/hr/[생성된 id]` 이동

---

### 3-3. 인사 상세 `/hr/[id]`

**헤더 카드**: 이름 / 고용형태 태그 · 재직상태 태그 · `{직무} · {입사일 라벨}` / 우측 `참여 프로젝트` · `진행중` 카운트

**탭**: `인사정보` · `프로젝트`

#### `인사정보` 탭

| 카드 | 항목 |
| --- | --- |
| 사람 정보 | 이름(View) · 주민번호(View, 마스킹) · 전화번호(Edit) · 이메일(Edit) |
| 근태 정보 | 입사일/계약시작일(View) · 계약형태(View) · 직무(Edit) · 재직상태(View) |
| | **정직원만** — 퇴사일 (date, `min = 입사일`) |
| | **용역만** — 계약종료일 (date) + 비활성화 라디오(활성 / 비활성화) |

- 하단: `변경사항 저장` · `되돌리기` + dirty 상태 표시
- 계약서 카드: 업로드된 파일 목록 + 드롭존 (PDF · 이미지)

**API**: `GET /api/v1/persons/{id}`, `PATCH /api/v1/persons/{id}`, `POST /api/v1/attachments`

#### `프로젝트` 탭

3열 카드 그리드. 각 카드: 프로젝트명 · 진행상태 태그 · 시작일 · 담당 · 역할
클릭 → `/projects/[id]`

**API**: `GET /api/v1/persons/{id}/projects`

## 4. 거래처관리

### 4-1. 거래처 목록 `/clients`

| 영역 | 구성 |
| --- | --- |
| 헤더 | `거래처관리` / `거래처 목록` / `거래처 등록` 버튼 |
| 필터 | 검색 인풋 (거래처명 · 대표명 · 담당자명 · 담당자 연락처, 340px) · 우측 `총 N곳` |
| 테이블 | 거래처명 · 사업자등록번호 · 대표명 · 담당자 · 프로젝트(우측정렬) · 진행여부 · 누적 계약액(우측정렬) |

- 진행여부 태그: `진행` → `tag-accent`, `잠재` → `tag-outline`, `진행완료` → `tag-neutral`

**API**: `GET /api/v1/clients?q=&page=&size=`

---

### 4-2. 거래처 등록 `/clients/new`

760px 단일 카드, 2열 그리드.
거래처명* · 사업자등록번호* · 대표자명* · 업종 · 대표전화 · 대표 이메일 · 사업장 주소 · 홈페이지 · 거래처 설명(textarea)

**API**: `POST /api/v1/clients` → 성공 시 `/clients/[id]` 이동
사업자등록번호 중복(`409`) 시 해당 필드에 에러 표시.

---

### 4-3. 거래처 상세 `/clients/[id]`

**헤더 카드**: 거래처명 / 진행여부 태그 · `{사업자등록번호} · 대표 {대표자명}` / 우측 `프로젝트` 수 · `누적 계약액`

**탭**: `기본정보` · `업무정보` · `문서`

#### `기본정보` 탭

| 영역 | 구성 |
| --- | --- |
| 좌 | 거래처 정보 편집 폼 (9개 필드) + `변경사항 저장` |
| 우 상 | 담당자 목록 + `담당자 추가` (다이얼로그: 이름 · 직책 · 전화번호 · 이메일) |
| 우 하 | 진행여부 태그 + `프로젝트 상태로 자동 판정` 안내 |

**API**: `GET /api/v1/clients/{id}`, `PATCH /api/v1/clients/{id}`, `POST /api/v1/clients/{id}/managers`

#### `업무정보` 탭

| 영역 | 구성 |
| --- | --- |
| 좌 상 | 요구사항 및 특이사항 (textarea) + `메모 저장` |
| 좌 하 | 프로젝트 테이블 — 프로젝트명 · 시작일 · 마감일 · 참여자 · 진행여부 · 계약금액 |
| 우 상 | 계약 누적액 — 계약금 / 수령 / 미수금 |
| 우 하 | 계정관리 (추후 기획 placeholder) |

**API**: `GET /api/v1/clients/{id}/projects`

#### `문서` 탭

사업자등록증 파일 목록 + 드롭존.

**API**: `POST /api/v1/attachments` (`ownerType=CLIENT_BIZ_LICENSE`)

## 5. 프로젝트관리

### 5-1. 프로젝트 목록 `/projects`

| 영역 | 구성 |
| --- | --- |
| 헤더 | `프로젝트관리` / `프로젝트 목록` / 스코프 안내 문구 / `프로젝트 개설` 버튼 |
| 필터 | 검색 인풋(프로젝트명·거래처명, 310px) · 세그먼트(전체 / 예정 / 진행중 / 완료) · `검색 결과 N건 · {범위}` |
| 테이블 | 프로젝트명 · 거래처 · 계약기간 · 실제 종료일 · 계약금액 · 진행상태 · 담당자 |
| 하단 | 페이지네이션 + `한 화면 12개` |

**중요**
- `overdue == true` 인 행은 **계약기간 셀을 빨간 글씨**로 표시한다.
- 용역 계정: `프로젝트 개설` 버튼 숨김, 계약금액 `비공개`, 스코프 안내 문구 표시

**API**: `GET /api/v1/projects?q=&status=&page=&size=12`

---

### 5-2. 프로젝트 개설 `/projects/new`

| 영역 | 구성 |
| --- | --- |
| 좌 (660px) | 프로젝트명* · 거래처 선택* · 계약 시작일 · 계약 종료일 · 계약금액 · 업무 담당자(정직원 select) |
| 우 (300px) | `계약기간 ≠ 운영기간` 안내 패널 |

- 계약 종료일은 시작일 이전 선택 불가 (`min` / `max` 상호 바인딩)
- 계약금액 세 자리 콤마 자동

**API**: `POST /api/v1/projects` → 성공 시 `/projects/[id]` 이동

---

### 5-3. 프로젝트 상세 `/projects/[id]`

**헤더 카드**: 프로젝트명 / 진행상태 태그 · `{거래처} · 담당 {담당자}` / 우측 계약금액 · `프로젝트 종료` 버튼

**탭**: `기본정보` · `참여인력` · `계약서`

#### `기본정보` 탭

| 영역 | 구성 |
| --- | --- |
| 좌 (420px) | 프로젝트명 · 거래처 · 계약기간 · 실제 종료일 · 진행상태 · 담당자 (View) + 계약금액 (Edit) |
| 우 | 프로젝트 상세내용 textarea + `내용 저장` |

- 용역 계정: 계약금액 자리에 `비공개` 텍스트, 저장 버튼 미노출

#### `참여인력` 탭

5열 그리드 — 참여인력 · 구분 · 역할 · 용역비 · 상태

| 상황 | 용역비 표시 |
| --- | --- |
| 정직원 멤버 | `—` (흐린 색) |
| 용역 멤버 / 정직원·마스터가 조회 | 편집 가능한 인풋 |
| 용역 멤버 / 용역 본인이 조회 | 본인 행만 실값, 타인은 `비공개` |

- `인력 추가` 다이얼로그: 인력 select · 역할 · 용역비 (정직원 선택 시 용역비 비활성)
- 인력 이름 클릭 → `/hr/[id]` (용역 계정은 클릭 불가 → 권한 다이얼로그)
- 퇴사자도 목록에 남고 상태 태그로 현재 상태를 표시

**API**: `GET /api/v1/projects/{id}`, `POST|PATCH|DELETE /api/v1/projects/{id}/members`

#### `계약서` 탭

파일 목록 + 드롭존.

**API**: `POST /api/v1/attachments` (`ownerType=PROJECT_CONTRACT`)

#### 프로젝트 종료 다이얼로그

실제 종료일 입력(`min = 계약 시작일`) → `종료 처리` 시 진행상태 `완료`.
안내: "실제 종료일을 입력하면 진행상태가 '완료'로 변경됩니다. 계약 종료일은 그대로 유지됩니다."

**API**: `POST /api/v1/projects/{id}/close`

## 6. 상태 표시 규약

| 값 | 태그 클래스 | 색 |
| --- | --- | --- |
| 재직 · 진행중 · 진행 | `tag-accent` | accent-100 / accent-800 |
| 예정 · 잠재 | `tag-outline` | 투명 + accent 보더 |
| 퇴사 · 완료 · 진행완료 | `tag-neutral` | neutral-100 / neutral-800 |

| 포맷 | 규칙 |
| --- | --- |
| 전화번호 | `000-0000-0000` (10자리는 `000-000-0000`) |
| 사업자등록번호 | `000-00-00000` |
| 주민등록번호 | `9601**-*******` |
| 금액 | 세 자리 콤마, 단위 없음 |
| 날짜 | `YYYY-MM-DD` |
